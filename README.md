# mikrotik-awg-setup

Выборочный VPN на MikroTik: домены из `domains.txt` (по умолчанию Claude, ChatGPT, Gemini и прочие AI-сервисы) идут через AmneziaWG, остальной трафик напрямую. Работает для всех устройств в сети, на них самих ничего ставить не надо

- AmneziaWG 3.x (включая 3.1: `HeaderProtectionKey`, `RandomTrailers` и т.д.) в контейнере RouterOS
- несколько серверов: работает первый живой, при падении переключается на следующий и потом возвращается обратно
- kill switch: если все сервера лежат, трафик к доменам из списка не уходит и напрямую
- поддомены подхватываются сами, можно добавлять и подсети
- скрипты на Python, работают на Windows и Linux

Обкатано на **hAP ac2** (ARMv7, 128 MB RAM, 16 MB флеша) с RouterOS 7.25

## Зачем контейнер и флешка

RouterOS сама умеет только обычный WireGuard, а его в РФ режет ТСПУ. AmneziaWG есть только в виде [amneziawg-go](https://github.com/amnezia-vpn/amneziawg-go), поэтому он запускается в контейнере из образа [drkivi/amneziawg-for-armv7](https://github.com/drkivi/amnezia-wg-docker)

**Без USB-флешки не получится.** Образ в распакованном виде весит ~30 MB, а на встроенной памяти hAP ac2 свободно меньше 1 MB, и освободить там нечего. Требования к флешке:

- любая от 2 GB, USB 2.0 хватит
- форматировать не нужно: подойдёт и ext4, и fat32, и ntfs, данные на ней останутся. Скрипт создаёт на ней папку `mikrotik/` с файлом `vpn.img` на 1 GB и форматирует в ext4 только этот файл
- в `vpn.img` лежат контейнер, конфиги и swap на 256 MB для RouterOS
- флешка должна оставаться в роутере всегда. Если её вытащить, VPN перестанет работать, а сам роутер и обычный интернет продолжат

## Что нужно

- MikroTik на ARM с RouterOS **7.15+** и USB-портом. Образ по умолчанию собран под armv7 (hAP ac2, hAP ac3 и т.п.), для arm64 укажи другой образ в `ROS_IMAGE`
- физический доступ к роутеру: один раз нажать reset, без этого RouterOS не включит контейнеры
- дефолтный конфиг firewall (defconf): список интерфейсов `LAN` и правило `defconf: fasttrack`
- клиентские конфиги AmneziaWG, по одному на сервер. Под роутер лучше выпустить отдельных пиров
- комп в той же сети с Python 3.10+, `pip install -r requirements.txt`

## Установка

0. **Бэкап.** В winbox: Files > Backup или `/system backup save name=before-vpn` и скачать файл себе

1. **RouterOS 7.15+.** Если стоит 6.x, сначала через канал upgrade, потом обычный stable:
   ```
   /system package update set channel=upgrade
   /system package update install
   # после ребута
   /system package update set channel=stable
   /system package update install
   # после ребута обновить загрузчик
   /system routerboard upgrade
   /system reboot
   ```
   После обновления ssh-ключ роутера поменяется, удали старый: `ssh-keygen -R 192.168.88.1`

2. **Публичный DNS на роутере** вместо провайдерского:
   ```
   /ip dhcp-client set [find interface=ether1] use-peer-dns=no
   /ip dns set servers=1.1.1.1,8.8.8.8
   /ip dns cache flush
   ```
   Роутер будет перехватывать DNS со всей локалки (см. ниже), а DNS некоторых провайдеров подменяет ответы. Например, на любое имя `.local` отдаёт `127.0.0.200`, и тогда перестают находиться устройства в сети: шары, принтеры, ssh на `имя.local`. С публичным DNS такого не бывает ни с какой зоной. Если WAN не `ether1`, поправь интерфейс

3. **Скрипты:**
   ```
   git clone https://github.com/crutch12/mikrotik-awg-setup
   cd mikrotik-awg-setup
   pip install -r requirements.txt
   cp .env.example .env     # в Windows: copy .env.example .env
   ```
   Впиши в `.env` адрес и пароль роутера. Один раз зайди по ssh руками, чтобы ключ роутера попал в `known_hosts`: `ssh admin@192.168.88.1`

4. **Конфиги серверов** положи в `servers/` как `awg-1-main.conf`, `awg-2-reserve.conf` и т.д. Порядок по алфавиту: первый основной, остальные запасные

5. **Подготовка роутера.** Вставь флешку и запускай, пока не напишет, что роутер готов:
   ```
   python vpn.py prepare
   ```
   За несколько запусков он поставит пакет `container` (ребут), включит контейнеры (тут нужно коротко нажать reset на роутере, роутер перезагрузится) и создаст `vpn.img` на флешке

6. **Установка:**
   ```
   python vpn.py install
   ```
   Роутер скачает образ с Docker Hub (~16 MB), распакует его на флешку и запустит

7. **Проверка:** `python vpn.py status`, а в браузере https://claude.ai/cdn-cgi/trace должен показать IP сервера

В Linux вместо `python` может понадобиться `python3`

## Команды

```
python vpn.py prepare     подготовить роутер: пакет container, device-mode, vpn.img на флешке
python vpn.py install     поставить всё
python vpn.py status      состояние, память, лог контейнера
python vpn.py off         выключить, всё ходит напрямую, контейнер останавливается
python vpn.py on          включить
python vpn.py sync        после правки domains.txt
python vpn.py conf        после замены конфигов в servers/ или правки awg/start.sh
python vpn.py uninstall   снести всё, что поставил install
python stresstest.py      скорость и нагрузка на роутер, напрямую и через vpn
python ros.py "/system resource print"   любая команда на роутере
```

## Как устроено

- роутер отвечает на DNS-запросы, и если домен из `domains.txt`, кладёт полученные адреса в address-list `vpn-ai` (`/ip dns static` с `type=FWD` и `match-subdomain=yes`)
- DNS из локалки на любые сервера (8.8.8.8 и т.п.) перехватывается роутером, иначе он не увидел бы домены
- поэтому роутеру нужен публичный DNS (шаг 2): все запросы локалки теперь идут к нему, и если там провайдерский DNS с подменой ответов, ломаются имена `.local` и прочее. Сам трафик перехват не трогает, в VPN уходят только адреса из списка
- адреса вида `192.168.x.x` и имена `.local` (mDNS) работают как раньше, DNS-сервер для них не нужен
- трафик к адресам из списка помечается в mangle и уходит по отдельной таблице маршрутов в контейнер через veth
- в контейнере `awg/start.sh` держит поднятым один туннель. Каждые 10 сек он пингует через него 9.9.9.9, после 3 провалов подряд (~30 сек) поднимает следующий сервер, а раз в 5 минут проверяет, не ожил ли основной. Запасные туннели не держатся запущенными, так экономится память
- если контейнер умер, маршрут уходит в blackhole: мимо VPN ничего не утекает

## Производительность hAP ac2

| | скорость | CPU | свободно RAM |
|---|---|---|---|
| VPN выключен | | ~2% | ~42 MB |
| VPN включён, покой | | ~4% | ~28 MB |
| напрямую | ~90 Мбит | ~10% | |
| через VPN, 1-4 потока | 16-22 Мбит | 60-80% | от ~20 MB |
| через VPN, 8+ потоков | контейнер упирается в лимит, его убивают, через ~10 сек он сам поднимается | | роутер живой |

Для AI-сервисов этого с запасом. Для видео и тяжёлых закачек нужен роутер помощнее (hAP ax2/ax3, 1 GB RAM)

Железо тут на пределе: amneziawg-go работает в userspace, на ~20 Мбит съедает весь CPU и раздувается до 30+ MB, а RouterOS самой нужно ~80 MB из 128. Поэтому настройки такие:

- `memory-max=32M` у контейнера. С большим лимитом роутеру может не хватить памяти, и он перезагрузится
- swap только для RouterOS, контейнеру он запрещён (`swap-max=1`): выгруженный на флешку туннель замирает намертво
- `GOMEMLIMIT` не ставить: Go уходит в бесконечную сборку мусора, и скорость падает до нуля
- `/queue simple` на veth контейнера ломает трафик

## Нюансы

- маршрутизация идёт по IP из DNS. Gemini сидит на общих IP Google, ChatGPT на общих IP Cloudflare, так что вместе с ними в VPN может попасть и чужой трафик на те же адреса
- если устройство резолвит DNS мимо роутера (DoH в браузере, корпоративный VPN со своим DNS), домены для него не сработают. На такой случай в `domains.txt` можно писать подсети, у Anthropic это `160.79.104.0/23`
- после `on` и `sync` устройства могут ещё несколько минут держать старые DNS-ответы в своём кэше
- IPv6 лучше держать выключенным (`/ipv6 settings set disable-ipv6=yes`), иначе часть трафика может пойти мимо туннеля
- при загрузке роутера контейнер может стартовать раньше, чем подмонтируется флешка. Он перезапускается сам, в логе будут ошибки `filesystem not mounted`, это нормально
- перенос на другую флешку: `vpn.py off`, выключить роутер, скопировать папку `mikrotik/` на новую флешку, включить. Если имя раздела поменялось, поправь путь у диска `vpnimg` в `/disk`

## Откат

- `python vpn.py off` выключает VPN, всё остальное остаётся на месте
- `python vpn.py uninstall` удаляет всё, что поставил `install`. Пакет container, device-mode и `vpn.img` на флешке остаются, их можно убрать руками
- полный откат: восстановить бэкап из шага 0
